# dashboard-palette-design

为数据看板、分析报告、监控界面设计配色的方法论与可直接取用的色板配方，以技能（skill）形态交付。

不含依赖，不需要安装。核心内容是三条纪律加三套配方：色阶锁定色相、彩色只承担语义、对比度靠计算。

## 内容

| 文件 | 说明 |
|---|---|
| `SKILL.md` | 主文件。三条纪律、三套配方、工作流程、反模式 |
| `reference/palettes.md` | 完整色板变量、场景变体、组件级用色规则 |
| `reference/contrast.md` | 对比度计算方法、实测对照表、修正策略 |

## 三套配方

| 配方 | 场景 | 主色 |
|---|---|---|
| A 深色看板 | 行情、监控、驾驶舱 | `#0b1220` 冷蓝底 + `#4ea1ff` 强调 |
| B 浅色报告 | 对外交付、消费数据 | `#f5f6f8` 冷灰底 + 品牌色 |
| C 中性工具 | 编辑器、控制台 | `#181818` 纯中性灰 + 橙色品牌 |

## 三条纪律

1. **色阶只改明度，锁死色相** — 四个背景层级的色相波动控制在 5 度内，饱和度递减、明度递增
2. **彩色只带语义** — 一个品牌强调色 + 一组涨跌色 + 少量状态色，其余交给灰阶
3. **对比度是算出来的** — 正文 ≥12，次要文字 5-7，彩色 ≥4.5，不达标调明度而非加粗

## 一个容易被忽略的点

涨跌色要按目标用户的文化约定选。国际市场绿涨红跌，A 股红涨绿跌。给国内用户看了绿涨红跌的界面，属于信息错误，不是风格差异。

## 何时有用

- 让 AI 生成 HTML 看板或报告，需要稳定好看的配色
- 现有界面说不上哪里怪，需要定位
- 深色与浅色主题要共用一套设计语言
- 文字可读性存疑，需要可计算的判断依据

## 何时没用

- 需要完整设计系统（组件库、动效、排版比例），这里只覆盖颜色
- 追求强视觉冲击的营销页，这套方法偏向克制与可读
- 已有成熟品牌规范且不能改动

## 来源

色值来自三份实际交付的 HTML 界面与一个商业桌面客户端的样式表，对比度按 WCAG 2.1 公式逐项计算，非目测估计。
