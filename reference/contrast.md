# 对比度计算与校验

配色是否"看得清"不该靠目测。这份文档给出可复现的计算方法、实测对照表和修正策略。

---

## 公式

WCAG 2.1 定义的对比度：

```
对比度 = (L亮 + 0.05) / (L暗 + 0.05)
```

其中 L 为相对亮度，范围 0（纯黑）到 1（纯白）：

```
对每个通道 c（取值 0-1）：
  c' = c / 12.92                    若 c ≤ 0.03928
  c' = ((c + 0.055) / 1.055) ^ 2.4  否则

L = 0.2126 * R' + 0.7152 * G' + 0.0722 * B'
```

那个 2.4 次幂是 sRGB 反伽马，不能省略。直接用 RGB 平均值算会得出错误结果，浅色区域的误差尤其大。

## 计算步骤

1. 十六进制转 RGB，每通道除以 255
2. 每通道做反伽马
3. 按 0.2126 / 0.7152 / 0.0722 加权求和得 L
4. 两个 L 代入比值公式

## 判定阈值

| 用途 | AA | AAA | 本项目建议 |
|---|---|---|---|
| 正文 | 4.5 | 7 | ≥ 12 |
| 次要文字 | 4.5 | 7 | 5 - 7 |
| 彩色语义（涨跌、状态） | 4.5 | 7 | 6 左右 |
| 大字号（≥18pt 或 14pt 粗体） | 3.0 | 4.5 | ≥ 4.5 |
| 纯装饰、分隔线 | 无要求 | 无要求 | 3.0 |

正文建议做到 12 以上，是因为深色背景上的文字会自动降低有效对比：屏幕反光、亮度调节、环境光都会削弱可读性。留出余量比刚好达标更稳妥。

## 修正策略

对比度不足时，按此顺序尝试，越靠前对整体观感影响越小：

1. **调明度**。同色相下把前景压暗（浅色底）或提亮（深色底），色相不变，风格不受影响。
2. **调背景**。前景保持不变，把卡片底色往反方向推一档。适合前景色由品牌规定、不能改的情况。
3. **加大字重或字号**。降低阈值要求（大字标准 3.0），但这是妥协，不是解决。
4. **换色相**。最后手段，会破坏色板一致性。

避免的做法：加文字阴影、加描边、加半透明底衬。这些都会让文字边缘变糊，实际可读性反而下降。

## 快速估算

手边没有工具时，用明度差粗判：

- 明度差（HSL 的 L）大于 60：对比度通常 > 7
- 明度差 40 至 60：对比度约 4.5 至 7
- 明度差小于 30：对比度很可能不足 4.5

只适用于同一色相的两色，跨色相会失效（红绿即使明度相同，对比度也可能差别很大，因为绿色在亮度公式中权重最高 0.7152）。

## 常见错误配对

| 问题配对 | 对比度 | 修正 |
|---|---|---|
| 深色底 + 纯白 `#ffffff` | 17.9 | 降到 `#e8eefc`，减少刺眼感，观感更好 |
| 品牌红 `#e1251b` 做小字 | 4.69 | 换 `#c8161d`，或提升到 16px 以上 |
| 灰色 `#999` 放白底 | 2.85 | 不符合 AA，改 `#767676`（4.54） |
| 浅蓝 `#60a5fa` 放白底 | 2.54 | 小字不用，改 `#2563eb`（5.17） |
| 深色卡片内用 `#444` 做次要文字 | 1.6 | 深色主题的次要文字必须提亮，不是压暗 |

最后一条最容易搞错：深色主题的"次要"意味着**降低与背景的亮度差**，但方向是提亮而非压暗。在 `#0b1220` 上，次要文字应落在 `#93a0b8` 这种中高明度区间。
